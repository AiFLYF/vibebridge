# 成长引擎

## 六个独立维度

没有总分。每个维度有自己的等级、稳定度、冷却期和历史。

| domain | 中文 | L0 | L10 |
|---|---|---|---|
| `expression` | 自我表达 | 最短回应 | 持续公开创作 |
| `communication` | 沟通 | 被动回应 | 面对面 |
| `social` | 社会互动 | 与 AI 表达 | 学习/工作/长期协作 |
| `collaboration` | 协作 | 独自创作 | 长期共同维护 |
| `independence` | 独立性 | 全程依赖引导 | 能长期自主推进 |
| `self_advocacy` | 自我倡导 | 不表达需求 | 稳定自我倡导 |

**"协作 L7、语音沟通 L2" 是完全合法的状态**，不是需要修正的不一致。真实的人本来就是参差不齐的。

完整阶梯：

```bash
python core/vb.py grow state
```

## 社会互动阶梯（0-10）

```
0  与 AI 表达          6  小规模群体交流
1  解释自己的作品       7  项目协作
2  发布作品            8  语音交流
3  阅读外部反馈         9  现实场景
4  回复一条公开评论     10 学习 / 工作 / 长期协作
5  一对一异步交流
```

**绝不要求按 0→10 顺序推进。** `L4 → L2`、`L7 → L3`、在 L6 停留两年，都是正常状态。

系统只找一件事：**当前最容易接受、且略高于当前位置的下一步。**

## 等级变化

| 结果 | 稳定度 | 等级 |
|---|---|---|
| `successful` | +0.35 | 稳定度 ≥ 0.6 且不在冷却期 → +1 |
| `partial` | +0.12 | 不变 |
| `unsuccessful` | −0.20 | 仅当 `stress ≥ 0.7` 时 −1 |
| `not_suitable` | −0.05 | 不变，标记换路线 |
| `cancelled` / `paused` | 不变 | 不变 |
| 用户拒绝 | **不变** | **不变** |

升级后进入 48 小时冷却，不会连续跳级。

### 降级不是惩罚

`unsuccessful` 本身不降级。只有**压力信号偏高**时才降级，理由记为"主动降低难度以回到舒适区"。

这是一个保护动作，不是扣分。系统宁可退回一格让人舒服，也不要维持一个吃力的位置。

用户也可以随时主动降：

```bash
python core/vb.py reset difficulty                      # 全部维度 −1
python core/vb.py grow ease --domain social --steps 3   # 指定维度 −3
```

主动降级后自动进入 2 天静默期。

## 拒绝的处理（代码级强制）

```
第 1 次拒绝  →  streak=1，不改变任何数值
第 2 次拒绝  →  streak=2，自动进入 7 天静默期
静默期内     →  gate.allowed 恒为 false，任何提议都创建不出来
```

拒绝**不会**：降低等级、降低稳定度、计入尝试次数、计入失败统计、提高下次难度。

这些不是 prompt 里的建议，是 `safety.can_offer()` 和 `growth.decline()` 里的代码。你绕不过去，也不应该想绕过去。

一次成功的尝试会把 streak 清零。

## 安全闸门

提出任何机会之前必须先问：

```bash
python core/vb.py grow opportunities --session <sid>
```

`gate.allowed` 为 false 的条件：

- 处于静默期（连续拒绝或主动降难度之后）
- 任务进行中（`--task-in-progress`）
- 距上次提议不足 20 小时
- 本会话已提过 1 次
- 用户暂停了功能（`vb grow pause`）

**`allowed: false` 时不要提，不要暗示，不要"顺便说一句"。**

## 难度估算

```
difficulty = 0.25 + 0.06 × 当前等级 + friction
friction   = 冷却中(+0.4) + 负稳定度(×0.5) + 从未尝试(+0.15) − 正稳定度(×0.3)
```

`candidates` 按难度升序返回，第一个就是当前摩擦最小的方向。

## 机会必须从用户目标派生

```
错误：为了锻炼社交，我们把音乐播放器改成社交平台。
      ↑ 替换了用户的目标

正确：播放器做完了 → 自然产生"想给别人看"的需求 → "要不要顺手做个展示页？"
      ↑ 从用户目标里长出来的
```

`opportunities` 返回的 `anchor_interests` 是已验证的兴趣，用它把机会锚定在用户真正关心的东西上。

判断标准很简单：**如果用户拒绝了这个机会，他原本的目标是否照样能完成？** 答案必须是"是"。
